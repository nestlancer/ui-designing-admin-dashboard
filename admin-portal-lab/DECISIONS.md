## F01 · Auth · Operator sign-in

- **Hand-authorship:** All F01 variants (V1–V5) were hand-authored; no design-generation script was used. (master §1.3)
- **Tokens:** `shared/tokens.css` created with EXACTLY master §5.2 CSS; all 5 variants `@import` it via `<link>` plus `shared/base.css` (reset + primitives only). Teal only — no blue, no second brand hue (C5).
- **Cookie banner (C15):** removed from every variant — the captured Dismiss/Accept banner is not rendered.
- **Dark mode (C18):** every variant ships a working theme toggle + `?theme=dark|light` boot before paint + `.dark` token overrides. Dark parity is real here.
- **Logo alt (C20):** logo is inline SVG with `role="img"` + `<title>Nestlancer Admin</title>` and `aria-label` on every variant; shared copy in `assets/logo.svg`.
- **Mono (C9):** session references (e.g. `auth_sess_12345678`) render in `var(--mono)`.
- **AA badges (C3):** PASS/PENDING badges = icon + colour + darkened AA text from status tokens; never colour alone.
- **Demo-only CTAs / lab affordances:**
  - The in-page "Demo state" chip row (Sign-in / Invalid / Expired / 2FA) is a lab affordance to preview the states the API returns; it is not a product feature.
  - Form `action` points at the real Gate-A endpoints (`POST /api/v1/auth/login`, `POST /api/v1/auth/verify-2fa`); the lab is a static mock, so submit is intercepted and shows the loading → invalid-credentials demo path. No real action is wired.
  - "Client sign-in", Terms, Privacy link to the captured real URLs (`https://app.nestlancer.com/...`).
- **A11 coverage:** expired-session notice ("Your session expired — sign back in…", finding #3: refresh 409/503) present in 5/5 variants (requirement ≥3/5), now dismissible (GitHub session-alert pattern).
- **Enterprise-standards pass (2026-11-01, after studying 12 live login pages — AWS, Google Cloud, Azure/M365, Salesforce, Cloudflare, Datadog, Stripe, Vercel, GitHub, Atlassian, DigitalOcean, Heroku; see docs/TEMPLATE-RESEARCH.md Gate T-2):**
  - Progressive disclosure (email → Next → password with Change back-link) in V2/V3/V5; enterprise single-page form in V1/V4. Frozen labels unchanged.
  - "Forgot password?" link — Gate-A-backed (`POST /api/v1/auth/forgot-password`); the reset-sent notice reuses the spec's 200 copy verbatim. Demo-labelled here because the lab is static.
  - Consent line under submit ("By continuing, you agree to our Terms and Privacy Policy.") with the captured real URLs; © 2026 Nestlancer + Secured·HTTPS chip in footers.
  - Error summary = `role="alert"` notice that takes focus; field errors via `aria-invalid` + `aria-describedby`; caps-lock hint via `getModifierState`; shared-device hint on "Keep me signed in"; autofocus first field; 44px targets on coarse pointers.
  - Deliberately NOT adopted: SSO/provider buttons, region/language pickers, marketing panels (not Gate-A/ADD-backed; report says no SSO/passkey for admin v1).
- **2FA step:** spec-backed (auth.openapi.json `202 TwoFactorChallengeDto`, `POST /api/v1/auth/verify-2fa` with `authSessionId`, 6–10 char `code`, `method totp|backupCode`). No SSO/passkey invented.

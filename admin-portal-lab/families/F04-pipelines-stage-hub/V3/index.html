GET /api/v1/admin/payments

Captured inventory below, prefix shorthand preserved. Published paths use /api/v1 and {id}. Request-payment path differs: published POST /api/v1/admin/milestones/{id}/request-payment. These are references only; no actions run.

  • GET /admin/payments — List payments
  • GET /admin/payments/:id — Payment detail
  • POST /admin/payments/:id/refund — Process refund
  • POST /admin/payments/:id/verify — Verify payment
  • POST /admin/payments/:id/approve-transfer — Approve offline bank/UPI transfer
  • POST /admin/payments/:id/reject-transfer — Reject offline bank/UPI transfer
  • GET /admin/payments/accounts — List platform settlement accounts
  • POST /admin/payments/accounts — Create platform settlement account
  • GET /admin/payments/milestones — Milestone payments
  • GET /admin/payments/milestones/:id — Milestone detail
  • PATCH /admin/payments/milestones/:id — Update milestone payment
  • POST /admin/payments/milestones/:id/request-payment — Request payment
  • Historical only: POST /admin/payments/projects/:projectId/milestones — removed in published Payments spec; do not call. Projects/Progress milestone routing needs integration verification.
  • GET /admin/payments/disputes/:id — Dispute detail
  • POST /admin/payments/disputes/:id/respond — Respond to dispute

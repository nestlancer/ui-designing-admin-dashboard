# F16 API map — documented, not live-verified

Full per-operation and schema inventory (all 40 users-service paths plus related admin-service paths): [OPENAPI-INVENTORY.md](OPENAPI-INVENTORY.md). Screenshot/account reconciliation: [REVIEW-EVIDENCE.md](REVIEW-EVIDENCE.md).

`users.openapi.json`: GET/PATCH/DELETE `/api/v1/admin/users/{userId}` (delete described as soft-delete), PATCH `/role`, PATCH `/status`, POST `/force-password-reset`, POST `/reset-password` (newPassword min 8), GET `/sessions`, DELETE `/api/v1/admin/users/sessions/{sessionId}`, POST `/terminate-all-sessions`, POST `/export`, GET `/activity`, POST `/restore`; GET `/api/v1/admin/users/logs` audit list. Status enum ACTIVE/SUSPENDED/DELETED/PENDING_DELETION; update DTO firstName, lastName, email, status. `admin.openapi.json`: POST `/api/users/{userId}/impersonate`, POST `/api/users/impersonate/end` or `/end/{sessionId}`, GET `/api/users/impersonate/sessions`; GET `/api/audit/user/{userId}` and audit list/detail. The API document does not establish runtime ACL, sole-admin enforcement, upstream gateway routes, live health, specific audit write or undo behavior. Six hub categories need service-by-service mapping and cannot be implied by user-profile endpoints. Static prototype prepares only; no network, production authorization, session, deletion, password or audit event.

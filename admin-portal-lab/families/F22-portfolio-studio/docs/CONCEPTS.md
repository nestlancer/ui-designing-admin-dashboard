# F22 · Revision-2 concepts

3 November 2026. Supersedes the historical revision-1 concepts. Research and these five directions were first recorded in `REVISION-2-RESEARCH-AND-PLAN.md` before the revised markup. Prompt addendum was synchronized during implementation, not before the initial HTML edits.

## Common organization

`Portfolio → Items | Categories | Analytics`

Default Items contains only collection totals, search/status, public-order review and item actions. Taxonomy and engagement are one-click peer workspaces. Source differences and prototype states live behind disclosure. No KPI wallpaper, fake project imagery or repeated warning panels. All use the same teal tokens, eight captured records, four labels, honest source gaps and guarded local actions.

Editing opens a dedicated viewport-sized workspace: section navigation, grouped fields, sticky review action. Review → Back retains values; dirty Escape/Cancel offers Keep editing / Discard. Shared local runtime is intentional; layouts were manually authored, not generated from one variant.

## V1 · Collection manager — minimal
**Sketch:** sidebar | heading → task tabs → compact totals → toolbar → aligned collection.
**Primary job:** find a case study and edit it with few competing surfaces.
**Hierarchy:** title and publication context, then dates and compact overflow. Stable columns replace scattered metadata. Minimal default recommendation, not owner approval.
**Research influence:** Directus table anatomy, Carbon toolbar and row consistency, Strapi browsing/editing separation.

## V2 · Case-study library — gallery-led
**Sketch:** sidebar | heading/tabs → compact collection heading → toolbar → 4/3/2/1 title cards.
**Primary job:** scan the collection visually without implying missing images exist.
**Hierarchy:** larger title and small sequence marker; publication/date strip and actions anchored to the card base. No giant fabricated covers.
**Research influence:** Directus card/table choice; Sanity collection browsing; no imported template artwork.

## V3 · Editorial workspace — document-led
**Sketch:** sidebar | heading/tabs → compact totals → narrow selectable roster | broad case-study context.
**Primary job:** choose a case study, understand its available public content, then edit.
**Hierarchy:** selected document title and known description; disclosure for captured full source; explicit unknown states for uncaptured editors. The full editor remains separate from this context pane.
**Research influence:** Sanity Structure Tool's list/document separation, Payload's distinction between preview and live-site embedding. This is an offline preview, not a live public-site iframe.

## V4 · Operations register — dense ledger
**Sketch:** sidebar | heading/tabs → small inventory/shortcut rail | dense aligned collection.
**Primary job:** repeated compact register operations and public ordering.
**Hierarchy:** smaller rows and tight aligned rank/title/status/date/action columns. Inventory counts and keyboard reference are a quiet local tool rail, not taxonomy/analytics panels. At smaller widths the rail becomes a strip before the register.
**Research influence:** Carbon dense-table rhythm, Tabler header/toolbar/row structure. No unrelated business dashboard metrics.

## V5 · Timeline curator — motion-led
**Sketch:** sidebar | heading/tabs/totals → toolbar → October chapter | single ordered timeline.
**Primary job:** review and arrange the public sequence without duplicating the workset.
**Hierarchy:** explicit position and title; all captured projects share October 2026. No fabricated completion dates. Transform-only entry reveals, IntersectionObserver and reduced-motion bypass; no animated metrics.
**Research influence:** sequence/review separation and GOV.UK review/back affordances. The chronology does not pretend unknown category assignments are known.

## Difference review
Axes: A geometry, B visual hierarchy, C narrative/job sequence, D density/surface, E interaction.
- V1/V4 are the closest pair intentionally: full-width minimal register vs denser register with tool rail (A/B/D). Their content and safety actions remain consistent rather than inventing alternate backend functions.
- V2 changes A/B/D and collection-reading narrative; V3 changes A/B/C/E through selection/context; V5 changes A/B/C/E through a single month spine and sequence narrative.

Inventory below, prefix shorthand preserved. Published paths use /api/v1 and {id}. Request-payment path differs: published POST /api/v1/admin/milestones/{id}/request-payment. These are references only; no actions run.

  • POST /api/v1/admin/payments/{id}/approve-transfer — Approve offline bank/UPI transfer
  • POST /api/v1/admin/payments/{id}/reject-transfer — Reject offline bank/UPI transfer
  • GET /api/v1/admin/payments/accounts — List platform settlement accounts
  • POST /api/v1/admin/payments/accounts — Create platform settlement account
  • GET /api/v1/admin/payments/milestones — Milestone payments
  • GET /api/v1/admin/payments/milestones/{id} — Milestone detail
  • PATCH /api/v1/admin/payments/milestones/{id} — Update milestone payment
  • POST /api/v1/admin/payments/milestones/{id}/request-payment — Request payment
  • Historical snapshot: POST /api/v1/admin/payments/projects/{projectId}/milestones — removed in published Payments spec; do not call. Projects/Progress milestone routing needs integration verification.
